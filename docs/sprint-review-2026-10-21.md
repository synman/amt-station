# amt-console sprint: final adversarial review

Review, 2026-10-21, of the console sprint `cf588c9..6c431f5` (28 commits, 110 files). Every citation is
`file:line` at `6c431f5` (HEAD). Read cold, after the per-packet sonnet reviews. The brief: find what a
per-packet review cannot see, which is cross-packet seams, contracts that drifted between packets, invariants that
hold per page and break in composition, and tests that pass without testing.

Method. I read the backend (`console/server.py`, `mcp_client.py`, `auth.py`, `webauthn_min.py`, `intake.py`,
`images.py`, `captures.py`, `embed.py`, `fleet.py`, `power.py`), the component layer (`static/components.js`,
`embed.js`) and the server-side contracts the console depends on (`amt_mirror.py`, `amt_serial.py`,
`amt_upload.py`, `amt_write.py`, `amt_captures.py`, `amt_identity.py`, `amt_fleet.py`), the C8 verifier
(`console/tests/test_console_verifier.py`, `design/check_mockups.py`) and the test doubles. I ran eight test
files at HEAD (`test_console_embed.py`, `test_console_captures.py`, `test_console_secrets.py`,
`test_console_mcp_client.py`: 163 passed, 11.6 s; `test_console_power.py`, `test_console_fleet.py`,
`test_console_manage.py`, `test_console_logs_inventory.py`: 287 passed, 4 min 16 s) and five probe scripts
against the suite's own fakes
(`console_fakes.FakeAmt`, `FakeViewer`, headless Chromium). No real host, NAS, vault or network was touched. No
repo file was changed except this one. The probes are in the session scratchpad
(`fable-review/probe_static.py`, `test_probe_nobrowser.py`, `test_probe_browser.py`), not committed.

A finding marked **confirmed** has a reproduction or an exact code trace. One marked **hypothesis** does not.

## Verdict

**Ship after fixes.** The console's core claims hold where the packets tested them: no console-side write path
into amt-mcp's state apart from one relayed route, the bearer and every one-time url masked in `/api/call`,
the intake value never kept or echoed, passkey-only sign-in with exact-Origin and CSRF checks, `confirmed: true`
refused before send on every write. The sprint-wide failure is in composition: the relay that keeps the viewer
token out of the browser (packet C4) serves amt-mcp's viewer page on the console's own origin, and the iframe
grants it `allow-same-origin`. Code served by the viewer front then holds the console session: it reads the CSRF
token, sends `amt_power hard_reset confirmed: true` through `/api/call` with no sheet and no hold, and rewrites
the console page (reproduced). The design's security model (section 2.1) assumed a cross-origin frame; the build
removed that assumption and two tests pin the new state as correct. One blocker, two majors, six minors. The
verdict is ship after fixes, not do-not-ship, because the blocker's fix is bounded (two known shapes, both
below) and no path for untrusted content into the frame was found; the majors are small.

## Invariants checked

1. **No console write path into amt-mcp's state.** Holds, with M1 as the one relayed exception. `console/` holds no vault, devices or image-root code; `fleet.py` reads only; `host-sessions.json` and the capture store are the console's own state.
2. **One-time urls never reach the browser.** Holds through `/api/call` (`strip_one_time_urls`, `mask_one_time_urls`; suite green), the embed relay (every session token and url replaced; suite green), uploads and intakes (opaque ids, url kept in memory). Fails through the four fleet and power error fields (M2). Access log: `loggable()` masks the upload and intake ids; the mint reply is not logged.
3. **No secret in a tool argument, result, response, log or file.** Holds by trace: `intake.py:71-125` reads the value once, PUTs it once, pops the id before the PUT, returns only `name` on a `stored: true` 201 (matches `amt_upload.py:248`), withholds any other answer that contains the value, and the vault CLI never echoes the body (`amt_upload.py:211-255` read). The manage suite's scan with a positive control covers it.
4. **Every write needs `confirmed: true`.** Holds on the console's own controls: `confirmedCall` adds it at sheet build, `sendCall` runs only from Confirm or a force fire, `validate_call` refuses a write without it before send (suite green). `stop`, `status`, `record_stop`, `list`, `verify` need none, which matches the tools (`amt_mirror.py:1167-1170`). Bypassable from the relayed frame (B1).
5. **Auth.** Holds. Routes without a session: `/signin`, `/static/<whitelist>`, the four `/auth/*` POSTs; every other GET and POST needs the cookie, every signed-in POST needs the CSRF token, every POST needs the exact `Origin` (and `Sec-Fetch-Site` when sent) and `Host`; WebAuthn verifies type, challenge (one-time), origin, `crossOrigin`, rpIdHash, UP+UV, ES256 on-curve, and the counter. The embed POST is cookie + Origin without CSRF by documented design.
6. **Vacuous greens.** Found: the two sandbox/policy tests that assert the defect (B1), the record-relay test that pins M1, the verifier that collects and never asserts `states`/`text`/`rings` (m1, m2), the 43-character static scans (m3), the skip-on-missing hue test (m4), the name-based no-retry test (m5). Not found: the mockup `secret_scan` body slice is non-vacuous on all 16 files (probed); the mask regex leaves every relayed asset byte-identical (probed); the `FAILS 0` builder is unit-tested branch by branch; the `disabled`, `motion`, `sheets` and `tables` counts are asserted non-zero in the aggregate.
