amt_device_manage takes the NAME of a vault entry that already exists in amt-mcp's vault, never a value. A value is entered in Identities, one time, through a one-time url.
With it, the add refuses any other leaf. Without it, the leaf the server presents during the add is pinned (trust on first use) and shown in the result; compare it with MEBx afterwards.
The TLS leaf is read during the add amt_device_manage opens one TLS handshake to the WS-MAN port, sends no credential, and pins the leaf it sees (or refuses when it differs from the expected pin). There is no separate read before the add; the pin appears in the result and on the table.

On add: the pin is recorded, the devices file is rewritten by amt-mcp (live at the next call), and a status read follows. Identities are named here, never entered: a value goes through a one-time intake in Identities.
