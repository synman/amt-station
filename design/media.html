Mount an image

When the host sees the drive next boot · waits; the host is not reset (default) graceful · asks the OS to reset now (the same act as Restart) now · HARD resets the host at once (hold to confirm)
the sheet follows the start mode you chose: a plain confirm, or the hold when the host is hard reset

Images must be .iso or .img under the root, a multiple of 512 bytes, read-only. One mount per host.

Mount debian-13.3-netinst.iso on my-server-1

The host's IDE-R session is opened and held until you unmount; the host sees a CD drive at its next boot and is not reset. KVM keeps working beside it.

tools/call amt_ider {device: "my-server-1", action: "mount", iso_path: "debian-13.3-netinst.iso", start: "next_boot", confirmed: true}

Mount debian-13.3-netinst.iso and HARD reset my-server-1 now

The image is attached and the host is reset at once without asking the OS: unsaved work is lost. The IDE-R session is held until unmount.

tools/call amt_ider {device: "my-server-1", action: "mount", iso_path: "debian-13.3-netinst.iso", start: "now", confirmed: true}

Hold 1.2 s and release, or press Enter and confirm on the next sheet

Mount debian-13.3-netinst.iso and HARD reset my-server-1 now

arms 400 ms after you release the key or the pointer

The host resets at once. Unsaved work is lost.

tools/call amt_ider {device: "my-server-1", action: "mount", iso_path: "debian-13.3-netinst.iso", start: "now", confirmed: true}

Unmount the image from my-server-1

Ends the IDE-R session. If the host is reading the drive, that read fails. If the serving thread will not stop, the session is reported as still held.

tools/call amt_ider {device: "my-server-1", action: "unmount", confirmed: true}

Fetch an image into the root

Downloads the URL into the image root on the server in the background; with a SHA-256 given, a mismatch deletes the file and reports failure. No host is touched.

tools/call amt_images {action: "fetch", url: "https://…/systemrescue-11.03-amd64.iso", name: "systemrescue-11.03.iso", sha256: "…", overwrite: false, confirmed: true}

Upload win11-24h2.iso from this computer

amt-mcp mints a one-time PUT url for exactly this size (and this SHA-256 if you give one); your browser sends the file to it once, straight to the image root, with progress in the library. A wrong size or hash is refused at the end and the part file is deleted. The file never passes through MCP or the console backend.

Rename ubuntu-24.04.3-live-server.iso

Renames the file in the image root. Refused if it is mounted, downloading or uploading. No host is touched.

tools/call amt_images {action: "rename", name: "ubuntu-24.04.3-live-server.iso", new_name: "ubuntu-24.04.3-server.iso", confirmed: true}

Delete ubuntu-24.04.3-live-server.iso

The file is deleted from the image root. There is no undo; fetch or upload it again if you need it. Refused if it is mounted, downloading or uploading.

tools/call amt_images {action: "delete", name: "ubuntu-24.04.3-live-server.iso", confirmed: true}

Change the image root

Points the library at another directory on the server (created if missing) and persists it ahead of the AMT_IMAGE_ROOT env. Mounted images keep serving.

tools/call amt_images {action: "set_root", root: "/iso", confirmed: true}
